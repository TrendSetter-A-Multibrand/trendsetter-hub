# Модуль «Склад» — приёмка по файлу

Перенос приложения «Склад-приёмка» (Google Apps Script: `Code.gs` + `Index.html`) в хаб. Функционал повторён как в исходнике, дизайн — хаба (Trendsetter), расположение кнопок — как в исходном приложении.

## Что внутри
- `lib/` — чистая логика без React, перенесена из `Index.html` без изменений поведения, покрыта тестами (`npm test`):
  `marks.js` (Честный знак: разбор DataMatrix, раскладка клавиатуры, GTIN/EAN), `plan.js` (раскладка из Excel, маршрутизация по коробкам, режим «без ЧЗ»), `code128.js`, `csv.js`, `print.js` (этикетки 58×40 — вёрстка как в оригинале намеренно), `localBackend.js` (серверная часть).
- `store.js` — состояние и сценарии (скан, закрытие короба, приёмки, импорт…), как в исходнике живёт вне React; React перерисовывается по `emit()`.
- `components/`, `WarehousePage.jsx`, `warehouse.css`, `strings.js` — интерфейс.

## Данные
Единственный шов — функция `api(name, ...args)` в `store.js`. Два хранилища с одним набором функций:
- `lib/httpBackend.js` — сервер хаба и база DigitalOcean (бэкенд `backend/app/modules/warehouse/`). Включается, когда задан `VITE_API_URL`. Данные общие для всех ПК: общий список приёмок, общая раскладка приёмки (сохраняется для всех ПК, остальные получают её автоматически и видят уведомление о новой версии), защита кодов ЧЗ между компьютерами, номера коробов и палеты без дублей.
- `lib/localBackend.js` — localStorage браузера. Используется в демо на Vercel (без `VITE_API_URL`): сценарии работают, но данные только в этом браузере.

Серверная часть: `service.py` (порт функций Code.gs, атомарность — функция `warehouse_next_box_number`, первичный ключ `warehouse_marks.ki`, `pg_advisory_xact_lock` для палетов), `router.py` (доступ — сотрудники отдела «Склад», admin, superuser), тесты `backend/tests/test_warehouse.py`. Таблицы — `db/modules/warehouse/001_warehouse.sql`. Отправка сканов идёт через очередь и `sync`: повтор пачки безопасен.

Состояние приёмки на экране и в выгрузках — это снимок из базы (`GET /modules/warehouse/receipt-state`, только чтение) плюс то, что сделано на этом ПК и ещё не дошло до базы. Слияние — чистая функция `merge()` в `lib/hydrate.js`, результат берётся через `view()` в `store.js`. Снимок хранится только в памяти (`S.db`), в `whf_state` не пишется. Перечитывается при выборе приёмки, при запуске и перед каждой выгрузкой; между ПК цифры сами не обновляются. Открытые короба других ПК и короба, перенесённые из старой системы во временных номерах, на ПК не берутся — они учитываются только в цифрах и выгрузках.

## ПИН ответственного
В исходнике ПИН зашит в `Code.gs`. В репозитории настоящего ПИНа нет. На сервере он задаётся переменной окружения `HUB_WAREHOUSE_PIN` (в `/opt/trendsetter-hub/.env`) и проверяется сервером; без неё доступ по ПИН отключён. В демо на моках стоит `DEMO_PIN` из `localBackend.js`.

Участник группы доступа с правом «Ответственный» по Складу проходит без ПИН: сервер отдаёт флаг `module_responsible.warehouse` в `/core/me`, интерфейс скрывает поле ПИН и отправляет пустой ПИН, сервер пропускает проверку и пишет в журнал `via = group` (по ПИН — `via = pin`). Остальным с правом запуска ПИН нужен как раньше. В демо (без `VITE_API_URL`) ПИН нужен всегда.

## Исходные материалы
Лежат локально в `modules/warehouse/` (папка в `.gitignore`: в `Code.gs` ПИН и почты, в `links.txt` ссылки на таблицу). Передавать через общий диск.

## Зависимость
`xlsx@0.18.5` (SheetJS, та же версия, что в исходном приложении) — чтение Excel; грузится лениво при выборе файла. У этой версии есть известные замечания `npm audit`; обновление идёт только через CDN-сборку SheetJS.
