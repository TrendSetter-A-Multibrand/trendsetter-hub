## Решения (не пересматривать без пользователя)
1. **Без миграции и без новых таблиц.** Только чтение того, что уже есть: `team_people`, `team_directions`, `team_form_fields`, `hr_employee_files`, `hr_leave_requests`. `hr_employee_sensitive` (оклад, реквизиты) **не читается вообще**.
2. **Считает бэкенд, одним эндпойнтом** `GET /modules/hr/stats`, с правом `Hr` (run на hr) — тем же, что у `GET /people/{id}/file`. Фронт получает только агрегаты и короткие списки людей. Дат рождения и возрастов конкретных людей в ответе нет.
3. **Охват.** Сотрудник = карточка `team_people` с `NOT is_archived`. Это то же, что фильтр «Работают» в таблице. Скрытые из карты (`show_in_map = false`) **входят** в охват (`TODO(Q-HA2)`). CEO и ассистент тоже входят. Статус определяется только по `is_archived`. Если `dismissed_at` уже прошёл, а карточка не в архиве, человек всё ещё считается работающим.
4. **Сводка общая по компании.** Она не зависит от поиска, фильтра направлений и выбора «Работают/Скрытые/Уволенные/Все» в таблице. Над блоком стоит подпись «По всей компании, на {дата}».
5. **Заполненность видна всегда.** Каждая разбивка по данным досье или анкеты возвращает `known`: у скольких людей значение указано. Под диаграммой стоит подпись «Указано у {known} из {total}». Пустые значения в кольцо **не входят** как сектор: доли считаются от `known`.
6. **Средние** (возраст, стаж) отдаются, только если `known >= 3` (`MIN_FOR_AVERAGE = 3`). Иначе `null`, и на карточке «—» с подсказкой «Мало данных».
7. **Возраст и стаж показываются только группами по всей компании.** Разрезов «возраст × направление», «стаж × направление» и подобных нет.
8. **Пол не показываем.** Поля нет нигде: ни в досье, ни в анкете, ни в импорте Google-формы. Пол не угадывается по отчеству или фамилии. Варианты — `TODO(Q-HA1)`.
9. **Оклады и фонд оплаты не показываем** (`TODO(Q-HA5)`).
10. **Больничные не показываются** ни в «В отпуске сейчас», ни в «Скоро в отпуске». Это совпадает с `service.calendar()`, `TODO(Q-HA3)`.
11. **Два источника географии не сливаются.** «Где работает» — это `answers.location`: ответ анкеты, варианты правит HR. «Страна оформления» — это `hr_employee_files.country` (RU/AM): от неё зависят нормы отпуска. Это две отдельные диаграммы, у каждой подписан источник (`TODO(Q-HA4)`).
12. **Чтение сводки в журнал не пишется**, как и календарь отпусков: в ответе нет ПДн сверх того, что HR видит в карточках.

## Приватность (почему так, а не иначе)
- **Кто видит.** Только `run` на hr. Эти пользователи и так открывают досье каждого человека с точной датой рождения и датой приёма. Поэтому сводка не расширяет круг доступа. Защищаемся от утечки через скриншоты и пересылку, а не от самого читателя:
  - нет дат рождения и возраста по людям;
  - нет перекрёстных разрезов (п. 7);
  - средние только при n ≥ 3 (п. 6);
  - нет денег (п. 9);
  - нет больничных (п. 10).
- **Почему не скрываем группы меньше 3 человек.** Внутри одного распределения скрытую группу легко восстановить: «всего» минус показанные группы. Пришлось бы скрывать ещё и итог, а сводка без итога бесполезна. При этом у читателя уже есть доступ к каждой строке. Поэтому группы 1–2 человека показываются как есть.
- **Жёсткое правило на будущее.** Если эндпойнт когда-нибудь откроют шире `Hr` (руководителям, `team`, на главную), это новое ТЗ с обязательным подавлением малых групп (k ≥ 3, включая итоги) и ревью приватности. Это правило записать комментарием в docstring `stats.py`.
- **`birthday_hidden` в возрасте учитывается.** Флаг управляет только публичным виджетом дней рождения, к HR он не относится.
- **Списки людей в ответе:**
  - отпуск сейчас и скоро (то же, что Team видит в календаре);
  - новички (HR видит их в таблице);
  - топ руководителей (структура и так видна в карте).

  В списках только `personId`, `name`, `directionId` и поля, перечисленные в контракте.

## Что есть в данных и что из этого строим

| Блок | Источник | Правило |
|---|---|---|
| Всего сотрудников | `team_people` | `count(*) WHERE NOT is_archived` |
| …с учёткой в хабе | `team_people.user_id` | `user_id IS NOT NULL` |
| …скрыты из карты | `show_in_map` | `NOT show_in_map` |
| Направлений | `team_people.direction_id` + `team_directions` | направления, где ≥ 1 человек; вывод по `team_directions.sort` |
| Команд | `team_people.team` | число различных непустых `trim(team)` без учёта регистра |
| Численность по направлениям | то же | `[{id, count}]`; цвет и подпись берутся из справочника направлений (бренд) |
| Где работает | ответ анкеты `location` (JSONB `answers`) | см. «Нормализация текста» |
| Формат работы | ответ анкеты `work_format` | см. «Нормализация текста» |
| Страна оформления | `hr_employee_files.country` | `RU` / `AM`; нет строки досье или NULL — не указано |
| Тип оформления | `hr_employee_files.employment_type` | `staff` / `gph` / `ip` / `other` |
| Возраст | `hr_employee_files.birth_date` | полных лет на сегодня; значения вне 14…100 считаются «не указано» |
| Стаж в компании | `hr_employee_files.hired_at` | только `hired_at <= today`; полных месяцев (`leave.full_months`) |
| Выходят на работу | `hired_at > today` | число; такие люди входят в «Всего», но не в стаж и не в новичков |
| Новички за 90 дней | `hired_at` | `today - 90 <= hired_at <= today` |
| Уволены за 90 дней | архив + `dismissed_at` | `is_archived AND today - 90 <= dismissed_at <= today` (архивные без `dismissed_at` не считаются) |
| На испытательном сроке | `probation_until` | `probation_until >= today AND (hired_at IS NULL OR hired_at <= today)` |
| В отпуске сейчас | `hr_leave_requests` | `status = approved`, `kind <> sick`, `start_date <= today <= end_date`, человек работает |
| Скоро в отпуске | то же | `today < start_date <= today + 14` |
| Руководители | `team_people.manager_id` | работающие, у кого ≥ 1 работающий прямой подчинённый (как `reports` в `PERSON_SQL`) |
| Средний охват | то же | сумма прямых подчинённых / число руководителей, 1 знак |

**Чего нет в данных:**
- **пол** (Q-HA1);
- город для РФ: в анкете только «Москва» и «Ереван», а «РФ, не Москва» можно получить, только если HR добавит вариант в поле `location` (без деплоя);
- дата основания компании и история численности — графика «численность по месяцам» нет (Q-HA6);
- `work_schedule` — свободный текст, не агрегируется.

### Группы (ключи — контракт; подписи — только во фронте, `strings.js`)
- Возраст: `under_25` (< 25), `25_34`, `35_44`, `45_54`, `55_plus` (≥ 55).
- Стаж: `lt_3m` (< 3 мес.), `3_12m` (3–11 мес.), `1_3y` (12–35 мес.), `3_5y` (36–59 мес.), `5y_plus` (≥ 60 мес.).
- Бэкенд возвращает **все** ключи группы в этом порядке, включая нулевые. Сумма `count` по группам равна `known`.

### Нормализация текста (`location`, `work_format`)
- Значение берётся как строка, `trim` и схлопывание пробелов. Пустое значение или не строка — «не указано».
- Группировка без учёта регистра (`casefold`).
- Подпись группы:
  - если значение совпадает (без учёта регистра) с вариантом из `team_form_fields.options` этого поля, подписью становится вариант;
  - иначе подпись — самое частое написание (при равенстве — первое по алфавиту).
- Порядок: по убыванию `count`, при равенстве — по подписи.
- Схлопывание хвоста в «Другие» делает **фронт** (см. ниже), бэкенд отдаёт все значения.

## API

`GET /modules/hr/stats` (prefix `/modules/hr`, право `Hr`; без параметров). Ответ (числа — int, если не сказано иное):

```json
{
  "asOf": "2026-10-27",
  "total": 42,
  "withAccount": 30,
  "hiddenFromMap": 2,
  "upcomingHires": 1,
  "directions": [{"id": "ops", "count": 7}, {"id": "mkt", "count": 5}],
  "teamsCount": 6,
  "location":       {"known": 38, "items": [{"label": "Москва", "count": 25}, {"label": "Ереван", "count": 13}]},
  "workFormat":     {"known": 35, "items": [{"label": "Гибрид", "count": 15}]},
  "country":        {"known": 20, "items": [{"key": "RU", "count": 12}, {"key": "AM", "count": 8}]},
  "employmentType": {"known": 20, "items": [{"key": "staff", "count": 17}, {"key": "gph", "count": 3}]},
  "age":    {"known": 18, "average": 31.4, "buckets": [{"key": "under_25", "count": 3}, {"key": "25_34", "count": 9}, {"key": "35_44", "count": 5}, {"key": "45_54", "count": 1}, {"key": "55_plus", "count": 0}]},
  "tenure": {"known": 20, "averageMonths": 27, "buckets": [{"key": "lt_3m", "count": 2}, {"key": "3_12m", "count": 4}, {"key": "1_3y", "count": 8}, {"key": "3_5y", "count": 4}, {"key": "5y_plus", "count": 2}]},
  "newcomers": {"days": 90, "count": 2, "people": [{"personId": 13, "name": "Захарова Полина", "directionId": "hr", "hiredAt": "2026-08-13"}]},
  "dismissed": {"days": 90, "count": 1},
  "probation": {"count": 2},
  "leave": {
    "soonDays": 14,
    "now":  [{"personId": 11, "name": "Саркисян Ани", "directionId": "buy", "kind": "annual", "start": "2026-10-20", "end": "2026-11-02"}],
    "soon": []
  },
  "managers": {"count": 8, "avgSpan": 3.4, "top": [{"personId": 10, "name": "Кравцов Денис", "directionId": "ops", "reports": 6}]}
}
```

- `country.items` и `employmentType.items` содержат только ключи с `count > 0`, в порядке констант `COUNTRIES` и `EMPLOYMENT_TYPES` из `service.py`. `directions` — только с `count > 0`, в порядке `team_directions.sort`.
- `age.average`: среднее полных лет, 1 знак, `null` при `known < 3`. `tenure.averageMonths`: среднее, округлённое до целого, `null` при `known < 3`. `managers.avgSpan`: 1 знак, `null` при `count = 0`.
- Сортировка списков:
  - `newcomers.people` — по `hiredAt` по убыванию, затем `personId`;
  - `leave.now` и `leave.soon` — по `start`, затем `personId`; в одном списке человек встречается один раз (самая ранняя заявка);
  - `managers.top` — до 10 записей, по `reports` по убыванию, затем имени.
- `name` — `"Фамилия Имя"`, как `service._name`.
- Запрещено в ответе:
  - ключ `birthDate`;
  - любые даты, кроме `asOf`, `hiredAt` новичков и `start`/`end` отпусков;
  - `salary`, `currency` и любые поля `hr_employee_sensitive`;
  - больничные.
- Ошибки: 401 без токена; 403 без `run` на hr (`m.FORBIDDEN`), как у остальных `Hr`-маршрутов.
- Запросы: несколько агрегирующих SQL, без запроса на каждого человека. Возраст и стаж допускается считать в Python по выборке `(birth_date, hired_at)` работающих: это одна строка на человека, не N+1. «Сегодня» — `date.today()`, как в остальном модуле; для тестов это параметр `today` у функции сервиса.
