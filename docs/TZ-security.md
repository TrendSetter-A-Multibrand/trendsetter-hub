## Решения (не пересматривать)
1. **Смена пароля сотрудником.** `POST /auth/change-password` `{oldPassword, newPassword}`: любой активный пользователь, только свой. Новый пароль ≥ 10 символов (по Unicode-символам), не совпадает со старым, ≤ 128 символов. После смены все прежние сессии пользователя недействительны; в ответе — новый токен, клиент подменяет сохранённый. Админский сброс пароля (реальный маршрут `POST /admin/users/{id}/password`, не менялся) тоже закрывает сессии этого пользователя. Журнал `core.password_change` / `core.password_reset` (только id).
2. **Закрытие сессий** — столбец `users.token_version int NOT NULL DEFAULT 0`; в JWT кладётся `tv`; `get_current_user` сравнивает; токены без `tv` считаются `tv=0` (чтобы не выбросить всех при выкате). Смена/сброс пароля увеличивает `token_version`.
3. **Журнал.** (a) Дополнительные записи: `hr.sensitive_view` (GET `/people/{id}/sensitive`), `hr.documents_list` (GET `/people/{id}/documents`) — только `person_id`, без значений; (b) эндпоинт чтения `GET /modules/hr/audit?personId=&action=&from=YYYY-MM-DD&to=YYYY-MM-DD&limit=50&offset=0` — доступ: `responsible` на `hr` ИЛИ администратор (`can_manage_users`); `limit ≤ 200`; возвращает `{items:[{id,at,userName,action,label,personId,personName,details}], total}`; `details` — белый список ключей (`person_id`, `document_id`, `category`, `kind`, `rows`, `sensitive`, `fields`, `count`, `template_id`, `year`), значений нет; охватывает действия с префиксами `hr.`, `team.`, а также `core.user_permission_set`, `core.password_change`, `core.password_reset`; `label` — читаемое название на русском (словарь действий в одном месте). (c) Просмотр журнала — по `GET /modules/hr/audit` пишет `hr.audit_view` (без фильтров, чтобы не раздувать).
4. **Автоистория оклада.** При `PATCH /people/{id}/sensitive`, если изменились `salary` или `currency`, автоматически создаётся запись истории `kind='salary'`, `auto=true`, `effective_date=сегодня`, `title='Изменение оклада'`, `old_value`/`new_value` — «120000.00 RUB» (текст), видна только `responsible` (как сейчас для salary). Если оклад ставится впервые (пустое → значение) — запись тоже создаётся (`old_value` NULL).
5. **Шифрование на уровне приложения.** Fernet (`cryptography`), ключ из переменной окружения `HUB_PII_KEY` (через запятую можно перечислить несколько ключей: первый шифрует, остальные только расшифровывают — ротация; используй `MultiFernet`). Шифруются: поля `hr_employee_sensitive.tax_id`, `social_id`, `passport`, `bank_details`, `bonus_note` (формат хранения `enc:v1:<токен Fernet>`) и содержимое `hr_document_files.content` (формат: 5 байт-префикс `ENC1\n` + токен Fernet). **Оклад (`salary` numeric) не шифруется** — осознанно (TODO(Q-S1): при необходимости перевести в зашифрованное поле отдельной миграцией). Чтение: значение с префиксом расшифровывается, без префикса считается открытым текстом (обратная совместимость). Запись без настроенного ключа: 503 «Ключ шифрования не настроен» для этих полей и для загрузки документов (чтобы случайно не писать ПДн открытым текстом); остальные поля работают. Неверный ключ/повреждённый токен при чтении → 500 без утечки деталей (в журнал уходит только тип ошибки). Ключ нигде не логируется и не попадает в ответы. Команда `python -m app.modules.hr.encrypt_existing [--apply]` (сухой прогон по умолчанию): шифрует все ещё открытые значения и документы; вывод — счётчики. Тест-ключ в тестах — генерируется в conftest.
6. **Индексы.** `CREATE INDEX IF NOT EXISTS audit_log_action_at_idx ON audit_log(action, at DESC)` и по `((details->>'person_id'))` для фильтра по человеку.

## API
- `POST /auth/change-password` (Me) → `{token}`; ошибки: 401 неверный старый пароль (сообщение «Неверный текущий пароль»), 422 короткий/совпадающий/слишком длинный пароль (понятные русские сообщения). Ограничение перебора: не более 5 неудачных попыток старого пароля за 15 минут на пользователя (счёт в памяти процесса допустим, TODO(Q-S2): общий счётчик при нескольких процессах) → 429 «Слишком много попыток, попробуйте позже».
- `GET /modules/hr/audit` — п. 3.
- Остальное — без изменения контрактов (шифрование прозрачно для клиентов).

## Уточнения координатора (2026-10-24)
- `GET /modules/hr/audit`: `action` — одно точное действие ИЛИ список через запятую (до 40, каждое формата `[a-z_]+\.[a-z_]+`, иначе 422); фильтр `IN`. Сотрудник — `personId`.
- Автоистория оклада: `old_value`/`new_value` — только число «120000.00» (без валюты). Смена одной валюты создаёт запись с одинаковыми old/new (валюта в текст не входит).
- Порядок проверок `POST /auth/change-password`: 429 (лимит) → 401 (старый пароль) → 422 (правила нового). Текст успеха показывает фронт («Пароль изменён. Остальные сессии закрыты.»).

## Отступления реализации (backend)
- Админский сброс: существующий `POST /admin/users/{id}/password` (в ТЗ был PATCH); действие журнала переименовано `user.password_reset` -> `core.password_reset`.
- Верхний предел пароля: помимо 128 символов действует предел bcrypt 72 байта (кириллица — до 36 символов); оба случая — 422 «слишком длинный». Минимум 10 символов только для смены сотрудником (админ по-прежнему задаёт от 8).
- `limit` > 200 или < 1, отрицательный `offset` — 422 (не обрезаются). Даты `from`/`to` — включительно, в часовом поясе `HUB_TIMEZONE`.
- Индекс по человеку назван `audit_log_person_idx`. Значения `details` вне белого списка и нескалярные (кроме списка строк) не отдаются.
- Ключ неверного формата (не Fernet) трактуется как «не настроен»: запись 503. Чтение зашифрованного значения без ключа — 503; неверный ключ — 500 «Не удалось прочитать защищённые данные» (в лог только тип ошибки).
- 503 при записи без ключа возникает только если в PATCH есть непустое значение зашифрованного поля (tax/social/passport/bank/bonus); очистка поля (null) и оклад/валюта/дни выплат работают без ключа.
- `encrypt_existing`: журнал `hr.encrypt_existing` (только счётчики) пишется при `--apply`; код выхода 2 без ключа. Устаревший открытый документ, начинающийся ровно с `ENC1
`, считался бы зашифрованным (на практике невозможно для pdf/jpg/png/office; для txt — крайне маловероятно).
- Счётчик попыток смены пароля сбрасывается успешной сменой; хранится в памяти процесса (Q-S2). В `conftest.clean` добавлен сброс счётчика и тестовый `HUB_PII_KEY` (генерируется при импорте); `08_security.sql` в `clean` не прогонялся (идемпотентный DDL без данных).
- В `requirements.txt` добавлен `cryptography` (уже была транзитивной зависимостью `python-jose[cryptography]`); Docker-образ пересобирать не обязательно, но желательно.
- В словарь подписей добавлены также `team.person_update/person_archive/seed_import/seed_rollback/import_responses` и `hr.reminders_run`.
