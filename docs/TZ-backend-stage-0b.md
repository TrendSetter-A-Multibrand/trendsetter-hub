# ТЗ: бэкенд хаба, этап 0b — каркас, вход по паролю, роли, админка

Статус: в работе (ветка dev-karen). Автор: lead-роль; реализация и проверки — по этому документу.

## Цель
Заменить моки фронтенда настоящим API для того, что уже есть в интерфейсе: вход по почте и паролю, профиль и права, управление пользователями и отделами. Модуль «Склад» и очередь задач — следующие этапы.

## Решения
- Стек: Python 3.13, FastAPI, SQLAlchemy 2, psycopg3, Alembic, python-jose (JWT), bcrypt.
- Данные: схема `trendsetter_hub` в базе `defaultdb` (таблицы уже созданы скриптами `db/`). Модели всегда с явной схемой, `search_path` не используется. `create_all` не вызывается.
- Два подключения: приложение — пользователь `hub_app` (без прав на изменение структуры), миграции — `doadmin`, только при деплое.
- Alembic: ревизия 0001 выполняет существующие `db/01_core_hub.sql` и `db/modules/warehouse/001_warehouse.sql` (один источник правды). В боевой базе таблицы уже есть, поэтому там выполняется только `alembic stamp head`. Таблица `alembic_version` лежит в схеме `trendsetter_hub`.
- Контракт API — моки фронтенда (`frontend/src/core/api/mock/handlers.js`): те же пути и формы ответов. Ошибки: `{"detail": "<русский текст>"}`.
- Пароль задаёт администратор при создании пользователя; сброс — администратор (письма не нужны). Пароль 8–72 байта.
- Токен — JWT в заголовке `Authorization: Bearer`. Каждый запрос перечитывает пользователя из БД и отклоняет отключённых.
- Демо-эндпоинты (`/auth/demo-*`) в бэкенде не существуют.
- `GET /core/runs` пока возвращает `[]` (таблицы задач нет).

## Эндпоинты
`GET /health` · `POST /auth/login` → `{token}` · `POST /auth/logout` · `GET /core/me` · `GET /core/runs?limit=` ·
`GET|POST /admin/users` · `PATCH /admin/users/{id}` · `POST /admin/users/{id}/password` ·
`GET|POST /admin/departments` · `PATCH /admin/departments/{id}`.

## Критерии приёмки
1. `pytest` в Docker зелёный на чистой БД, подготовленной ревизией Alembic; приложение в тестах подключается как `hub_app`.
2. Права `compute_module_access` совпадают со всеми 16 случаями `frontend/src/core/access.test.js`.
3. Логин: верный пароль → токен; неверный пароль, неизвестная почта, отключённый пользователь → одинаковый 401 «Неверная почта или пароль».
4. Отключённый пользователь с ранее выданным токеном получает 401.
5. Только `admin` управляет пользователями и отделами; самому себе нельзя сменить уровень и отключить.
6. Дубли почты и названия/кода отдела → 409 с текстом ошибки; невалидные данные → 422 с русским текстом.
7. CLI `create-superadmin` запрашивает пароль через `getpass`, не принимает его из аргументов и окружения.
8. В репозитории нет паролей и ключей; `.env.example` содержит только заглушки.
9. Фронтенд: при заданном `VITE_API_URL` экраны входа, главная и админка работают с настоящим API; без него (Vercel-демо) остаются моки.
