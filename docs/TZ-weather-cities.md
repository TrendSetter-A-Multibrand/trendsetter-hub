# ТЗ: погода на главной — «убрать город» и любой город мира

Статус: lead, 2026-10-30, по `main` @ `54c407b`. Открытые вопросы — `Q-WC*`, в коде — `TODO(Q-WCn)`. Факты о внешних источниках и библиотеках проверяет technical-analyst (раздел «Проверка фактов T-W*») **до начала PR 2**.

**Миграций БД нет ни в одном PR.** БД не используется: выбор города хранится в `localStorage`, справочник городов — статический файл в репозитории, кэш погоды — в памяти процесса. **Контракт `GET /core/home/weather` не меняется** (те же поля; меняется только множество допустимых `city`). Новых эндпойнтов нет.

## Задача пользователя
1. Выбранный «третий город» в погоде должен очевидно убираться (сейчас — только пункт «Не выбран» в выпадающем списке шестерёнки).
2. Город для погоды — «как в часах»: любой город мира с поиском и русскими названиями (сейчас белый список из 17 городов).
3. Подсказка «как одеваться» (`WeatherAdvice`) работает для любого выбранного города.

## Что есть сейчас (сверено с кодом)
- `backend/app/core/home.py`: `CITIES` — кортеж из 17 `{id, lat, lon, timezone}`; `DEFAULT_CITY_IDS = ("yerevan", "moscow")`; `weather_payload(city_id)` добавляет третий город, если `city_id` есть в `CITIES` и не в умолчаниях; иначе молча 2 города. URL к MET строится только из белого списка.
- Кэш `_weather: dict[id → state]` создаётся лениво и **ограничен размером белого списка**. Константы `MAX_CITIES` в коде **нет** — вытеснение придумывать не нужно (см. «Кэш и нагрузка на MET»).
- `weather_payload` держит глобальный `_lock` на время до 3 последовательных HTTP-запросов (таймаут 5 с): при холодном кэше и лежащем MET другие запросы главной ждут до ~15 с. Это не меняется (известное ограничение, `TODO(Q-WC9)`).
- `routes_core.py`: `GET /core/home/weather?city=` (`max_length=40`, длиннее → 422).
- Фронт: `myCity.js` (`CITY_ZONES` — копия 17 зон, `hub.myCity`, `loadMyCity` — неизвестный id → `null`, `clockSlots` — подпись и зона слота часов по умолчанию из `CITY_ZONES`), `CityPicker.jsx` (Select из 17 + «Не выбран»), `WeatherCard.jsx` (вкладки `.seg` с подписью `s.cities[id]`), `useHomeWeather.js` (запрос с `?city=`; при смене города старые `data` остаются до ответа — `loading` не выставляется), `WeatherAdvice.jsx` (город из `data.cities` по `cityId` — от списка 17 не зависит), `ClocksCard.jsx` (подпись `s.cities[z.cityId]`), `api/mock/home.js` (свой список 17 с условной температурой), `strings.js` → `hub.home.cities` (17 + `paris`, `newYork`), `myCityNone`.
- `backend/requirements.txt` уже содержит `tzdata`.

## Решение (рекомендация lead)

### Источник данных: статический справочник в репозитории
| Вариант | Итог |
|---|---|
| **GeoNames `cities1000` + `alternateNamesV2` (CC BY 4.0)** → сгенерированный файл в репо | **Рекомендуется.** Есть IANA-зона, население, тип пункта, русские названия; коммерческое использование разрешено при атрибуции; ноль внешних вызовов во время работы |
| Wikidata (CC0) | Русские подписи лучше, но зона (P421) — чаще смещение UTC, не IANA; нужен SPARQL. Отклонено; допустимо только для ручной сверки названий |
| Геокодинг Open-Meteo (API) | Бесплатный тариф, по нашим сведениям, только для некоммерческого использования (проверить — T-W3); плюс внешний вызов на каждый ввод, произвольные координаты от клиента, ещё один источник отказа. **Скорее отказ** |
| Бэкенд-эндпойнт со списком городов | Не нужен: список нужен фронту синхронно (подпись часов, вкладки), демо-режим на Vercel работает без бэкенда. Отклонено |

**Безопасность:** бэкенд принимает только `id` из белого списка и строит URL к MET только из своих `lat/lon` (4 знака). Никаких координат и названий от клиента — нет SSRF и нет «прогрева» MET произвольными точками.

### Состав справочника (Q-WC2)
Отбор из `cities1000` (feature class `P`), исключить коды `PPLX`, `PPLH`, `PPLQ`, `PPLW`, `PPLCH` (районы, исторические, заброшенные):
1. Все 17 текущих городов — **с текущими id и ровно текущими `lat/lon/timezone` из `home.py`** (см. «Идентификаторы»).
2. Все столицы стран (`PPLC`).
3. Все города мира с населением от 1 000 000.
4. Города с населением от 100 000 в RU, BY, KZ, KG, UZ, TJ, TM, AZ, AM, GE, MD, UA.
5. Армения (AM) — все с населением от 15 000.
6. Ручные списки `include`/`exclude` в файле переопределений (например, исключить районы-«города», если просочатся).

Дедупликация: при совпадении пары (русское название, страна) остаётся более населённый. Ожидаемый объём ≈ 900–1100 записей; тест допускает 700–1400. Если генератор даёт число вне диапазона — вернуть количество вопросом lead, правила отбора под диапазон не подгонять.

### Русские названия
- Из `alternateNamesV2`: `isolanguage = ru`, `isHistoric = 0`, `isColloquial = 0`; приоритет `isPreferredName = 1`, затем `isShortName = 1`, затем первое по порядку файла. Нет русского названия → запись **исключается** (кроме столиц и 17 текущих — для них название обязано быть в переопределениях).
- Переопределения имеют приоритет: для 17 текущих — ровно названия из нынешнего `strings.hub.home.cities` (Ереван, Москва, Санкт-Петербург, …, Алматы, Астана, Белград); плюс ручные правки, найденные при ревью.
- Альтернативные строки для поиска (`alt`) — **только из переопределений**, не из сырого GeoNames (там сотни вариантов): «Питер», «СПб», «Алма-Ата», «Нур-Султан», «Бомбей», «Kyiv», «Kiev» и т. п.
- Страна в подписи — через `Intl.DisplayNames` с локалью `ru` и `type: region` по коду страны (справочник стран не храним; ошибка или нет поддержки → код страны).
- Русские названия в файле данных — это **данные, а не UI-строки**; правило «все UI-строки — в `strings.js`» на них не распространяется (как на IANA-зоны). Комментарий об этом — в шапке файла данных.

### Идентификаторы и localStorage (Q-WC3)
- 17 текущих городов **сохраняют свои id** (`yerevan`, `moscow`, `saintPetersburg`, `kazan`, …). В переопределениях — явная карта «legacy id → geonameid»; легаси-запись **сливается** со строкой GeoNames с этим geonameid, а не дублирует её (иначе «Москва» дважды в списке и два запроса к MET на одну точку): id, name, lat, lon, timezone — из переопределений, `en`, `cc` и население — из строки GeoNames.
- Остальные: `g<geonameid>` (например, `g2643743` — Лондон). geonameid стабилен между выгрузками, slug из названия — нет.
- Ключ `hub.myCity` в localStorage — по-прежнему только id (строка). Миграции значения не нужно: старые id валидны.
- Сохранённый id неизвестен (мусор, город удалён из справочника) → `loadMyCity` возвращает `null`, третьего города нет, часы по умолчанию; без сообщений. Бэкенд на неизвестный id — прежние 2 города (как сейчас).
- Порядок выката: deploy.yml катит бэкенд раньше сайта. Если новый фронт всё же пришлёт `g…` старому бэкенду — придут 2 города, вкладки нет; безопасно.

### Кэш и нагрузка на MET (Q-WC5)
- Ничего не вытесняем. Ключи `_weather` — только id белого списка: не больше ~1100 состояний по единицам КБ, порядка 10 МБ в худшем случае. LRU по количеству **запрещён**: вытеснив город, мы перезапросим его раньше чем через час — нарушение «не чаще 1 запроса в час на точку».
- Нагрузка на MET ограничена сверху: не больше 1 запроса в час на точку × ~1100 точек ≈ 0,3 запроса/с в худшем случае; запросы идут последовательно под `_lock`. `Expires`, `If-Modified-Since`, `User-Agent` — как сейчас. Дополнительный лимитер не нужен.
- Если справочник когда-нибудь вырастет до многих тысяч записей — тогда добавить очистку состояний, не запрошенных 24 ч и дольше (не в этой задаче).
- `TODO(Q-H3)` (контакт в User-Agent) становится важнее с ростом числа точек; не блокирует.

### Размер данных во фронте
- Справочник фронта — JS-модуль (не JSON: импорт JSON в `node --test` требует import attributes) в компактном виде массива массивов `[id, name, en, cc, tz, alt]`; оценка 70–90 КБ, около 25 КБ gzip. Импортируется **статически**: нужен синхронно `clockSlots` и подписям вкладок; `HubPage` в основном бандле. Тест ограничивает размер файла 120 КБ. Рост gzip основного бандла — не более ~30 КБ.
- Координаты во фронт не попадают (не нужны).

### Поиск (как в часах, но с ранжированием)
- Чистая функция `searchCities(query, limit = 50)`: нормализация (нижний регистр, ё→е, дефисы, апострофы и точки → пробел, схлопывание пробелов, обрезка). Ключ поиска записи: русское название + `en` (ASCII-название GeoNames) + `alt` + транслит русского названия (упрощённая схема: ж→zh, х→kh, ц→ts, ч→ch, ш→sh, щ→shch, ю→yu, я→ya, й/ы→y, э→e, ь/ъ→пусто) + русское название страны.
- Ранжирование: (1) название начинается с запроса; (2) с запроса начинается любое слово ключа; (3) вхождение подстроки. Внутри группы — порядок справочника (население по убыванию). Не более `limit` результатов.
- Пустой запрос → 17 «популярных» (текущие города в текущем порядке).
- Исправление раскладки клавиатуры («vjcrdf») — не делаем.

### UX «убрать город» (Q-WC6)
- У вкладки третьего города (только если `myCity` не в умолчаниях) — соседняя кнопка-крестик в той же группе `.seg` (не вложенная в кнопку вкладки — это невалидный HTML): иконка `CloseOutlined`, `aria-label` и `title` «Убрать город {название} из погоды». Клик → `onMyCity(null)`.
- В окне шестерёнки пункт «Не выбран» из списка **убрать**; под Select — кнопка «Убрать город», видна только когда город выбран (покрывает и случай, когда «мой город» — Ереван или Москва и третьей вкладки нет).
- Мгновенность: вкладка исчезает сразу по клику, без ожидания сети — показываются только города из `DEFAULT_CITY_IDS ∪ {myCity}` из `data.cities` (фильтр в `useHomeWeather`). Тот же фильтр при смене A→B не показывает A.
- Фокус после удаления крестиком — на первую вкладку.
- Длинные названия (Петропавловск-Камчатский, Ростов-на-Дону): у подписи вкладки — многоточие и `title` с полным названием.
- Побочный эффект (ожидаемо, Q-AP3): незакреплённый слот часов 01 тоже вернётся к Еревану.

### Подсказка «как одеваться»
Логика не меняется: `WeatherAdvice` берёт `data.cities` (уже отфильтрованный хуком) и `cityId`; бэкенд считает слоты для третьего города тем же конвейером в зоне города из справочника; `adviceText` хэширует `cityId` — подходит любая строка. Нужно только проверить тестом мока и вручную.

### Атрибуция (Q-WC8)
- В окне выбора города (внизу Popover) — мелкая ссылка «Города: GeoNames (CC BY 4.0)» на https://www.geonames.org/ (по образцу «Данные: MET Norway»).
- В шапке файлов данных: источник, дата выгрузки, лицензия CC BY 4.0, пометка «данные изменены: выборка, русские названия уточнены вручную».
