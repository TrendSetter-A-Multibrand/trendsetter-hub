# ТЗ: разовый перенос данных Склада из Excel «Склад-приемка» в таблицы warehouse_* (WEEEK #18835)

Статус: утверждено пользователем 2026-10-19 (ответы на Q-M1…Q-M9 — в конце файла). Ветка `dev-karen`. Код ещё не написан.

## Цель
Одна команда, которая запускается на сервере. Она переносит данные старой системы на Google Apps Script (выгрузка xlsx) в таблицы `trendsetter_hub.warehouse_*`. После переноса склад продолжает работу в хабе: те же приёмки, короба на тех же палетах, коды ЧЗ защищены от повторной приёмки, номера коробов и палет без коллизий. Ещё команда умеет:
- сухой прогон;
- сверку с листом «Сводка»;
- откат до начала живой работы.

DDL, миграций и правок существующего кода Склада нет.

## Решения (предложены lead; спорные помечены Qn)
1. **Где и как запускается.** Команда `python -m app.modules.warehouse.legacy_import`.
   - Файл передаётся путём или через stdin (`-`). На сервере файл подаётся через `docker exec -i … < файл`, в контейнер он не копируется.
   - Режимы:
     - по умолчанию сухой прогон;
     - `--apply` — запись;
     - `--rollback` (с `--apply` или без) — откат.
2. **Одна транзакция на весь перенос.** Сначала `pg_advisory_xact_lock(LOCK_STORAGE)`, затем проверки, вставки и сверка.
   - Сухой прогон проходит тот же путь и в конце делает `ROLLBACK`. Ограничения БД проверяются по-настоящему. Побочный эффект — пропуски в identity, это безвредно.
   - При любой ошибке — `ROLLBACK`.
3. **Идемпотентность** держится на естественных ключах: `INSERT … ON CONFLICT DO NOTHING`. Для архива — `WHERE NOT EXISTS` по (`box_code`, `pallet_code`, `freed_at`).
   - Сначала проверка «в БД только данные этого файла». Если в любой таблице есть строки, которых нет в файле, — отказ (exit 2).
   - Повторный запуск после успеха даёт «вставлено 0» и ничего не коммитит.
   - Строки, которые уже есть, не обновляются.
4. **Метка источника без DDL (Q-M7)**: запись в `audit_log` с `action = 'warehouse.legacy_import'`, `module_id = 'warehouse'`, `user_id = NULL`. В `details`:
   - `file_sha256`;
   - `receipts` как `[{id, name}]`;
   - состояние после переноса: число строк по каждой таблице и приёмке, значения счётчиков и указателей, список доп. секций.
   - Никаких КИ и почт.
   - Откат читает последнюю такую запись (без отката) и удаляет по `receipt_id` и перечисленным ключам. Если текущее состояние отличается от записанного — значит, началась живая работа, и откат отказывает (exit 2).
5. **Часовой пояс**: `--tz`, по умолчанию `Europe/Moscow` (установлено по данным, подтвердить в Q-M3).
   - Самопроверка обязательна: для каждой строки «Раскладки» |Когда(tz) − Версия| ≤ 2 с, для каждого скана с ID `^W-(\d{13})-` |Время(tz) − ms| ≤ 5 с.
   - Если проверка не прошла — ошибка с подсказкой о найденном смещении.
   - Если проверять нечем — предупреждение.
6. **Сотрудники (Q-M1)**: «Кто» → `users.id` по `lower(email)`, неактивные тоже подходят.
   - Если почты нет в `users` — ошибка (exit 1). В отчёте выводится список почт, админ заводит учётки в админке и запускает повторно.
   - «Сотрудник» (имя ПК или фамилия) переносится в `worker` как есть, без нормализации регистра.
   - Пустое «Кто» → `NULL`.
7. **Дубли строк в файле.** Если строки полностью совпадают — берётся одна и пишется предупреждение (8 коробов в реальном файле, Q-M6). Если ключ одинаковый, а содержимое разное — ошибка.
8. **Незакрытые короба (Q-M2).** Сканы с временным кодом переносятся как история, с предупреждением и счётчиком. Номера временных кодов учитываются в счётчиках. Перед боевым запуском все короба должны быть закрыты.
9. **Строгость.** Любая битая строка — ошибка, ничего не пишется, выводятся первые 50 ошибок и их общее число. Флагов «пропустить» нет.

## Таблица соответствия
Общие правила преобразования:
- `int_(v)`: int; float без дробной части → int; строка из цифр → int; иначе ошибка.
- `text_(v)`: `None` → `""`; float без дробной части → `str(int)`; иначе `str(v).strip()`. `full_code` не обрезается.
- `dt_(v)`: `datetime` (naive) → `replace(tzinfo=ZoneInfo(tz))`. Строка `dd.mm.yyyy hh:mm[:ss]` разбирается так же. Пусто или иное → ошибка (для обязательных полей).
- `cat_key = key(text_(v))` → `"3"`. `cat_part = part(text_(v))` → `"03"`.
- Заголовки ищутся по названиям из строки 1. Лишние столбцы (в том числе формульный «Палет») игнорируются. Нет обязательного заголовка → ошибка. Строка пустая, если пусты все её исходные (не формульные) столбцы.

| Лист → таблица | Поле листа → колонка | Правила |
|---|---|---|
| Приемки → `warehouse_receipts` | Приемка → name; Создана → created_at; Кто создал → created_by; Статус → status | «открыта» → `open`, «завершена» → `finished`, иное — ошибка. Имя 1–80 символов. Дубль имени без учёта регистра — ошибка. Приёмка, на которую ссылаются другие листы, но которой нет в «Приемки», — ошибка. |
| Раскладки → `warehouse_receipt_plans` | Приемка → receipt_id; Версия → version (`int_`); Данные → data (части склеиваются по `int_(Часть)` 0..n-1 без пропусков, результат проходит `json.loads`); Файл → file_name; Загрузил → `"<worker> / <email>"` или `"<email>"` (делить по последнему `" / "`) → worker, uploaded_by; Когда → uploaded_at | Несколько версий у одной приёмки — берётся максимальная, предупреждение. Раскладка завершённой приёмки не переносится (хаб удаляет её при завершении), предупреждение. Пропуск части или битый JSON — ошибка. |

| Счётчики → `warehouse_pallet_pointers` | `PAL_<s>` → section=`part(s)`, current_pallet (`int_`, 1–6) | `ON CONFLICT DO NOTHING`. Другие ключи — предупреждение, не переносятся. |

| Короба → `warehouse_boxes` | ШК короба → code; Сотрудник → worker; Коробка → category (`cat_key`); Товаров → item_count (`int_`, ≥ 0); Открыт → opened_at; Закрыт → closed_at; Кто → closed_by; Приемка → receipt_id | Код в итоговом формате. Столбец «Палет» игнорируется. |

Коробов на палете больше `cap(p)` — предупреждение. |

## Проверки до записи (внутри транзакции, после блокировки)
**«В БД только данные этого файла».** Конфликт (exit 2), если есть хотя бы одно из:
- приёмка, которой нет в файле (сравнение по `lower(name)`);
- скан с `id` не из файла;
- короб или место хранения с кодом не из файла;
- строка архива не из файла;
- КИ не из файла;
- доп. секция не из файла;
- раскладка не для приёмки из файла или с другой версией;
- категория счётчика не из файла, либо `last_number` больше расчётного;
- указатель палета не из файла, либо значение отличается.

Отчёт по каждой таблице: сколько «чужих» строк и до 5 примеров ключей. Для КИ — только маска.

## Сверка (внутри транзакции, до commit)
- **(a) «Сводка» против сырых строк файла по каждой приёмке:**
  - scanned — число строк «Сканы»;
  - not_in_file — статус начинается с «нет в файле»;
  - surplus — статус начинается с «излишек»;
  - boxes_closed — строки «Короба»;
  - boxes_without_pallet — коды «Короба», которых нет в «Хранении»;
  - pallets — уникальные «Палет» в «Хранении»;
  - cz_codes — сканы с КИ;
  - marked_without_cz — статус оканчивается на «без ЧЗ».
  
  Расхождение → exit 3. Это значит, что выгрузка не согласована, нужна новая.
- **(b) `warehouse_receipt_summary` против файла после удаления дублей**, по тем же метрикам. Должны совпасть точно, иначе exit 3. Это ошибка переноса, флага обхода нет.
- **(c)** Для каждой категории `warehouse_box_counters.last_number` ≥ максимального номера в кодах **во всей БД**, иначе exit 3.
- В отчёте печатаются «Начало» и «Последний скан» из Сводки и из представления (в часовом поясе `--tz`) — только для глаз, не проверяются.

## Вопросы к пользователю (Qn) — с рекомендацией
- **Q-M1. Почты «Кто», которых нет в хабе.**
  - Рекомендация: ошибка, админ заранее заводит учётки (можно отключённые).
  - Альтернатива: `user_id = NULL`. Тогда «кто сделал» теряется навсегда — колонки для почты нет.
  - В файле 2 почты, одна из них может быть общим `warehouse@` — завести ли её пользователем хаба?
- **Q-M2. Незакрытые короба.**

### Шаг 3 — перенос
```python
@dataclass
class Report:
    exit_code: int
    lines: list[str]
    def text(self) -> str: ...

def import_workbook(session: Session, source, *, apply: bool, tz: str = SHEET_TZ) -> Report
```
Порядок:
1. `SELECT pg_advisory_xact_lock(:k)` с `service.LOCK_STORAGE`.
2. Чтение `users` (id, lower(email)).
3. Разбор. Если есть ошибки → `rollback`, exit 1.
4. Проверка «только данные файла». Если конфликт → exit 2.
5. Вставки в порядке: receipts → (выборка id по `lower(name)`) → plans → scans → boxes → storage_boxes → storage_archive → extra_sections → marks → box_counters (upsert `GREATEST`) → pallet_pointers.
6. Сверки (a), (b), (c). Не сошлось → exit 3.
7. Если `apply` и вставлено > 0:
   - `log_action(session, None, ACTION, service.MODULE_ID, file_sha256=…, receipts=[{id,name}], state={…})`, где `state` — по решению 4, без КИ и почт;
   - `commit`.
8. Иначе `rollback`. Если `apply` и вставлено 0 — строка «уже перенесено, изменений нет», exit 0.

### Шаг 4 — откат
`rollback_import(session, *, apply: bool) -> Report`:
1. Блокировка.
2. Последняя запись `ACTION`, на которую не ссылается ни одна запись `ACTION_ROLLBACK` (`details->>'import_audit_id'`). Нет такой → exit 2.
3. Сравнить текущее состояние с `details.state`: строки по приёмкам во всех таблицах, счётчики, указатели, секции. Есть отличия → exit 2 с перечнем («началась живая работа — автоматический откат невозможен»).
4. `DELETE` по `receipt_id` из записи: marks, storage_archive, storage_boxes, boxes, scans, plans. Затем секции, указатели и счётчики из записи, затем receipts.
5. При `apply`: `log_action(None, ACTION_ROLLBACK, import_audit_id=…, counts=…)` и `commit`. Иначе `rollback`.

## Риски
- **Неверный часовой пояс** сдвигает всю историю на час. Защита — самопроверка по epoch в ID и версии раскладки.
- **Живая система во время выгрузки** → незакрытые короба и расхождения. Защита — заморозка, свежая выгрузка, сверка (a).
- **Гонка с API во время записи.** Advisory-блокировка защищает только палеты и секции, а не `sync`/`marks`. Защита — заморозка и проверка «только данные файла» внутри транзакции.
- **Память контейнера** (512 МБ): `read_only=True` на 3 МБ — ожидается меньше 200 МБ. Работающий API делит лимит, поэтому запускать в тихое время.
- **Откат по журналу** возможен только до живой работы. Это ограничение принято осознанно (Q-M7).
