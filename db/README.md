# База данных хаба (PostgreSQL, DigitalOcean)

Здесь лежат SQL-скрипты, которыми создаётся база хаба. Секретов (паролей) в них нет.

## Как это устроено — простыми словами
На кластере DO (`db-postgresql-fra1-45348`) уже есть базы `defaultdb`, `purchasing_dashboard`, `airflow_db`. Хаб полностью отдельный проект, поэтому ему создаётся **своя база `trendsetter_hab`** (так же, как у дашборда закупок — отдельная база). Внутри неё:

| Уровень | Что это | Пример |
|---|---|---|
| **база** | отдельный «шкаф» хаба | `trendsetter_hab` |
| **схема** | «ящик» внутри базы: всё одного блока лежит вместе | `hub` — ядро (пользователи, роли, отделы, журнал); `warehouse` — модуль «Склад»; позже `purchasing`, `wb`… |
| **таблица** | сами данные | `hub.users`, `warehouse.scans` |

Новый модуль = новая схема со своими таблицами. Ядро и другие модули в неё не лезут. Приложение подключается отдельным пользователем `hub_app`: читает и пишет данные, но не может менять структуру. Структуру меняет только `doadmin` через эти скрипты.

## Что делать в pgAdmin (по порядку)
Один раз, под `doadmin`. Подключение к DO требует SSL (в pgAdmin в настройках сервера SSL mode = require; у вас уже настроено).

1. **`00_database_and_roles.sql`** — откройте Query Tool на базе `defaultdb`. Сначала замените `ЗАМЕНИТЕ_НА_СГЕНЕРИРОВАННЫЙ_ПАРОЛЬ` на длинный случайный пароль (только в окне pgAdmin, файл не сохраняйте). Выполните. Пароль `hub_app` сохраните в менеджере паролей. Вместо этого шага можно создать базу и пользователя в панели DO (Databases → Users & Databases).
2. Обновите список баз в pgAdmin (правая кнопка на Databases → Refresh), откройте Query Tool **на базе `trendsetter_hab`** и выполните **`01_core_hub.sql`** — ядро.
3. На той же базе выполните **`modules/warehouse/001_warehouse.sql`** — модуль «Склад».

Все скрипты можно запускать повторно: уже существующее они пропускают.

## Что в ядре (`hub`)
`departments` (отделы — справочник), `users` (вход по почте и паролю; пароль только хэшем; уровни admin / superuser / employee / viewer), `user_departments`, `module_departments`, `audit_log`. Первого администратора создаёт команда бэкенда (пароли в SQL не хранятся).

## Модуль «Склад» (`warehouse`)
Листы Google Таблицы «Склад-приёмка» превращены в таблицы: Приемки → `receipts`, Раскладки → `receipt_plans`, Счётчики → `box_counters` и `pallet_pointers`, Сканы → `scans`, Короба → `boxes`, Хранение → `storage_boxes`, Хранение — архив → `storage_archive`, Секции → `extra_sections`, Коды ЧЗ → `marks`, Сводка → представление `receipt_summary`. Условия, которые раньше защищал `LockService`, теперь держит сама база: уникальность кода ЧЗ, одно место на короб, одна приёмка с таким именем, номера коробов через функцию `next_box_number()`, повтор отправки скана отсекается по id.

## Как добавить новый модуль
Скопируйте `modules/_template.sql` в `db/modules/<имя>/001_<имя>.sql`, замените `<module>` и опишите таблицы. Выполните в pgAdmin на `trendsetter_hab`. Права для `hub_app` в шаблоне уже есть.

## Дальше
Когда появится бэкенд, эти скрипты станут первой ревизией Alembic (правило проекта: структуру меняет только Alembic). До этого изменения структуры — новыми файлами в этой папке, по номерам. Подключаться к боевой базе с машины разработчика для работы над кодом нельзя: для разработки используется локальный Postgres из docker compose.
